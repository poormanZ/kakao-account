# IRO (이로) 개발 기획

## 1. 게임 개요

**게임 제목:** IRO (이로)  
**서브타이틀(가칭):** 9 Grid Survival

3×3 카드 보드와 속성/직업 시너지를 이용해 몬스터를 처치하고, 최대 몇 라운드까지 생존할 수 있는지를 경쟁하는 턴 기반 생존 전략 미니게임이다.

핵심 재미는 매 턴 제공되는 3장의 카드 중 원하는 카드만 리롤하고, 1장을 선택해 보드에 배치/교체하면서 현재 보드의 시너지를 최적화하는 것이다.

---

## 2. 핵심 게임 루프

```text
ROUND 시작
  ↓
최대 9 TURN
  ↓
[카드 리롤]
  ↓
[카드 1장 선택]
  ↓
[3×3 배치 또는 기존 카드 교체]
  ↓
[속성/직업 시너지 계산]
  ↓
[몬스터 전투]
  ↓
몬스터 처치?
  ├─ YES → ROUND CLEAR → 다음 ROUND
  └─ NO  → 플레이어 생존 여부 확인 → 다음 TURN
                    ↓
              9 TURN 종료
                    ↓
              몬스터 생존
                    ↓
                 GAME OVER
```

### 라운드 규칙

- 각 라운드는 최대 9턴으로 진행한다.
- 9턴 안에 몬스터를 처치하면 다음 라운드로 진행한다.
- 9턴이 끝났는데 몬스터가 살아 있으면 게임 오버다.
- 플레이어 HP가 0이 되면 즉시 게임 오버다.
- 몬스터를 9턴보다 빨리 처치하면 즉시 라운드를 클리어한다.
- 최종 랭킹의 핵심 기준은 **최대 클리어 라운드**다.

---

## 3. 턴 진행

매 턴은 다음 순서로 고정한다.

```text
1. 카드 리롤
2. 카드 선택
3. 카드 배치/교체
4. 시너지 계산
5. 전투
6. 다음 턴 또는 다음 라운드
```

### 3-1. 카드 리롤

매 턴 3장의 후보 카드가 제공된다.

플레이어는 카드별로 `KEEP` 또는 `REROLL`을 선택할 수 있다.

예:

```text
🔥⚔   💧🛡   🌪🔮
KEEP  REROLL KEEP
```

리롤하지 않은 카드는 유지하고, 선택한 카드만 새 카드로 교체한다.

MVP 기본값은 **턴당 1회 부분 리롤**로 시작한다. 이후 게임 밸런스에 따라 리롤 횟수 증가 요소를 추가할 수 있다.

### 3-2. 카드 선택

최종적으로 보이는 3장의 카드 중 1장을 선택한다.

### 3-3. 배치/교체

- 보드에 빈칸이 있으면 선택한 카드를 빈칸에 배치한다.
- 보드가 완성된 이후에는 기존 카드 1장을 선택해 새 카드로 교체한다.
- 카드 교체는 기존 시너지를 깨뜨릴 수 있으므로 개별 카드 능력과 보드 시너지를 함께 판단해야 한다.

---

## 4. 3×3 보드

게임의 핵심 전략 공간은 3×3 보드다.

```text
┌─────┬─────┬─────┐
│     │     │     │
├─────┼─────┼─────┤
│     │     │     │
├─────┼─────┼─────┤
│     │     │     │
└─────┴─────┴─────┘
```

### 보드 구축

첫 라운드에서는 9턴 동안 카드 1장씩 배치해 보드를 완성한다.

```text
TURN 1 → 1장
TURN 2 → 2장
...
TURN 9 → 9장 / 3×3 완성
```

라운드 클리어 후에는 보드를 유지한다.

다음 라운드부터는 빈칸에 새 카드를 추가하는 대신 **기존 카드 교체를 통해 빌드를 개선**한다.

---

## 5. 카드 구조

모든 카드는 다음 두 가지 분류를 동시에 가진다.

```text
속성 + 직업
```

예:

```text
화염 전사
속성: 불
직업: 전사
```

### 속성 4종

| 속성 | 역할 방향 |
|---|---|
| 🔥 불 | 공격력, 치명타, 지속 피해 |
| 💧 물 | 회복, 피해 감소, 보호막 |
| 🌪 바람 | 속도, 연속 공격, 회피 |
| 🪨 땅 | 방어력, 최대 HP, 안정성 |

### 직업 4종

| 직업 | 역할 방향 |
|---|---|
| 🛡 탱커 | 방어, 피해 흡수, 보호 |
| ⚔ 전사 | 직접 공격, 물리 피해, 처치 보너스 |
| ❤️ 힐러 | 회복, 버프, 디버프 해제 |
| 🔮 법사 | 스킬 피해, 광역 공격, 특수 효과 |

기본 카드 조합은 `4속성 × 4직업 = 16종`을 MVP 기준으로 한다.

## 6. 시너지 시스템

가로 또는 세로로 연속된 3장의 카드가 같은 속성 또는 같은 직업이면 시너지가 발동한다.

### 속성 시너지

```text
🔥 🔥 🔥
```

→ 불 시너지

### 직업 시너지

```text
⚔ ⚔ ⚔
```

→ 전사 시너지

### 이중 시너지

하나의 3장 라인이 속성과 직업을 동시에 만족하면 두 시너지가 모두 발동한다.

```text
🔥⚔  🔥⚔  🔥⚔
```

→ 불 시너지 + 전사 시너지

### 판정 범위

- 가로 3칸: 3개 라인
- 세로 3칸: 3개 라인
- 대각선은 MVP에서 시너지 판정 대상이 아니다.

따라서 완성된 보드에서는 최대 6개 라인을 독립적으로 판정한다.

---

## 7. 시너지 설계 방향

정확한 수치는 플레이 테스트를 통해 조정한다. MVP에서는 각 시너지가 명확하게 다른 전략을 만들도록 설계한다.

### 속성 시너지

**불**
- 공격력 증가
- 치명타 확률 증가
- 지속 피해 강화

**물**
- 매 턴 회복
- 받는 피해 감소
- 보호막 강화

**바람**
- 추가 공격 확률
- 회피 확률
- 공격 속도/행동 보너스

**땅**
- 최대 HP 증가
- 방어력 증가
- 강한 피해 감소/보호막

### 직업 시너지

**탱커**
- 피해 감소
- 보호막
- 생존 보너스

**전사**
- 공격력 증가
- 치명타/처치 보너스

**힐러**
- 회복량 증가
- 지속 회복
- 버프 강화

**법사**
- 스킬 피해 증가
- 광역 피해
- 특수 효과 강화

---

## 8. 전투 시스템

시너지 계산 후 현재 보드의 전투 능력치를 적용해 몬스터와 전투한다.

기본 흐름:

```text
현재 보드
  ↓
시너지 활성화
  ↓
플레이어 전투 능력 계산
  ↓
몬스터에게 피해
  ↓
몬스터 반격
  ↓
플레이어 HP 확인
```

전투는 매 턴 종료 시 1회 진행한다.

### 설계 원칙

- 초반에는 보드가 약하므로 몬스터를 빠르게 죽이기 어렵다.
- 턴이 지날수록 시너지가 늘어나며 플레이어가 강해진다.
- 몬스터도 라운드가 올라갈수록 강해진다.
- 공격에 집중하면 9턴 제한을 유리하게 가져갈 수 있지만 생존이 위험해진다.
- 방어에 집중하면 오래 버틸 수 있지만 9턴 안에 몬스터를 죽이지 못할 수 있다.

즉 매 턴 다음 세 가지를 동시에 판단하게 한다.

```text
공격력
생존력
시너지 구조
```

---

## 9. 몬스터 시스템

매 라운드마다 하나의 몬스터가 등장한다.

몬스터는 기본적으로 라운드가 올라갈수록 HP와 공격력이 증가한다.

단순한 능력치 증가만으로 끝내지 않고 이후 특수 패턴을 추가한다.

예정 특성:

- 방어형: 방어력이 높음
- 회복형: 일정 턴마다 HP 회복
- 광역형: 플레이어에게 큰 피해
- 암살형: 특정 턴에 강한 공격
- 속성 저항형: 특정 속성 피해 감소

### 보스

특정 라운드마다 보스를 배치한다.

예정:

```text
5R  MINI BOSS
10R BOSS
20R ELITE BOSS
30R BOSS
...
```

보스는 일반 몬스터와 다른 특수 규칙을 가져 플레이어가 현재 빌드를 조정하도록 유도한다.

---

## 10. 라운드 구조

### Round 1

튜토리얼 성격의 첫 라운드.

- 빈 3×3 보드
- 9턴 동안 카드 배치
- 기본 속성/직업 시너지 학습
- 몬스터 처치

### Round 2+

완성된 보드를 유지한 상태로 시작한다.

- 매 턴 3장 후보
- 부분 리롤
- 1장 선택
- 기존 카드 1장 교체
- 시너지 재계산
- 전투

이 구조를 통해 게임은 다음 두 단계의 재미를 갖는다.

```text
Round 1
보드 구축

Round 2+
보드 최적화 + 생존
```

## 11. 게임 오버

다음 조건 중 하나를 만족하면 즉시 게임 종료한다.

1. 플레이어 HP가 0이 됨
2. 해당 라운드의 9턴이 종료되었는데 몬스터가 생존함

게임 오버 결과:

```text
GAME OVER

MAX ROUND
42

BEST ROUND
45

RANK
#128
```

## 12. 랭킹

핵심 랭킹 지표는 **최대 클리어 라운드**다.

권장 타이브레이커:

1. 최대 클리어 라운드
2. 해당 라운드의 몬스터 처치 턴
3. 남은 HP
4. 기록 생성 시각

단, 포털에서 노출하는 대표 기록은 최대 라운드 하나로 단순하게 유지한다.

### 계정 연동

게임 서비스는 `kakao-account`의 내부 `users.id`를 `account_user_id`로 사용한다.

Kakao 사용자 ID나 Access Token을 게임 데이터의 식별자로 사용하지 않는다.

## 13. 점수/기록 저장

MVP에서는 게임별 별도 점수 테이블을 사용한다.

예정 테이블:

```text
iro_scores
```

주요 필드:

```text
id
account_user_id
max_round
last_round_clear_turn
remaining_hp
created_at
```

사용자별 최고 기록을 기준으로 랭킹을 계산한다.

필요 시 이후 다음 데이터를 추가한다.

```text
run_id
build_snapshot_json
round_stats_json
synergy_stats_json
```

단, 랭킹 계산에 필요하지 않은 상세 플레이 데이터는 MVP에서 최소화한다.

## 14. API 설계 방향

예정 API:

```text
GET  /api/games/iro/ranking
GET  /api/games/iro/my-rank
GET  /api/games/iro/best
POST /api/games/iro/scores
```

### 점수 보안

클라이언트가 `max_round`를 임의로 제출하는 구조는 피한다.

기본 원칙:

```text
Browser
  ↓
Game Server
  ↓
입력/게임 결과 검증
  ↓
최종 기록 계산
  ↓
Game DB
  ↓
Ranking
```

MVP에서는 최소한 다음을 검증한다.

- 라운드/턴 값의 범위
- 음수 및 비정상적인 값
- 허용되지 않은 상태 전이
- 동일 플레이 세션의 중복 제출
- 인증된 `account_user_id`와 제출 사용자 일치 여부

경쟁성이 높아지면 서버 발급 run/session과 이벤트 검증을 추가한다.

## 16. UX 원칙

### 카드 선택

선택 가능한 카드와 현재 보드의 시너지 기여도를 즉시 알 수 있어야 한다.

### 배치

카드를 올릴 수 있는 칸을 명확히 표시한다.

### 시너지

시너지 발동 라인을 시각적으로 강조한다.

예:

```text
🔥 🔥 🔥
────────  FIRE SYNERGY
```

### 교체

Round 2 이후에는 제거되는 카드와 새 카드의 변경 효과를 미리 보여주는 것을 권장한다.

```text
교체 전
FIRE SYNERGY Lv.2

교체 후
FIRE SYNERGY Lv.1
WARRIOR SYNERGY Lv.1
```

플레이어가 결과를 예측한 후 교체할 수 있어야 한다.

## 18. 밸런싱 원칙

게임은 운보다 선택의 질이 결과에 큰 영향을 주도록 설계한다.

```text
랜덤성
= 어떤 3장이 나오는가

플레이어의 전략
= 무엇을 리롤할 것인가
= 어떤 카드를 선택할 것인가
= 어디에 배치할 것인가
= 무엇을 교체할 것인가
= 어떤 시너지를 유지할 것인가
```

특히 리롤은 완전한 재추첨보다 **부분 리롤**을 기본으로 하여 플레이어가 원하는 카드를 보존하면서 필요한 카드만 노릴 수 있게 한다.

---

## 19. 장기 확장 방향

### 카드 확장

- 희귀도
- 카드 레벨
- 특수 효과
- 전설 카드
- 동일 속성/직업의 변형 카드

### 빌드 확장

- 3개 동일 시너지 → 강화 시너지
- 여러 줄의 동일 시너지 → 상위 시너지
- 카드 세트 보너스
- 특정 속성 + 직업 조합 보너스

### 몬스터 확장

- 속성 저항
- 상태 이상
- 패턴형 보스
- 라운드별 환경 효과

### 경쟁 모드

모든 플레이어가 같은 카드 랜덤 시드를 공유하는 **Daily Seed**를 추가한다.

```text
같은 카드 순서
        ↓
같은 랜덤 조건
        ↓
누가 더 좋은 선택을 하는가?
        ↓
순수 전략 경쟁
```

---

## 20. 개발 우선순위

개발 순서는 다음을 권장한다.

```text
1. 게임 상태 모델
2. 카드/보드 모델
3. 리롤/선택 로직
4. 배치/교체 로직
5. 시너지 계산기
6. 전투 계산기
7. 9턴/라운드 상태 머신
8. 게임 UI
9. 서버 기록 저장
10. 랭킹
11. 밸런싱/UX 개선
```

게임 로직은 UI와 분리해 순수 함수/서비스 단위로 테스트할 수 있게 구성한다.

---

## 21. 개발 완료 기준

MVP는 다음 조건을 모두 만족하면 완료로 판단한다.

- 9턴 동안 보드가 정상적으로 구축된다.
- 원하는 카드만 리롤할 수 있다.
- 리롤하지 않은 카드가 유지된다.
- 매 턴 1장만 선택된다.
- 가로/세로 속성 시너지가 정확히 계산된다.
- 가로/세로 직업 시너지가 정확히 계산된다.
- 하나의 라인이 속성/직업 시너지를 동시에 발동할 수 있다.
- 몬스터를 9턴 안에 처치하면 다음 라운드로 넘어간다.
- 9턴 종료 후 몬스터가 살아 있으면 게임 오버된다.
- 플레이어 HP가 0이면 게임 오버된다.
- Round 2부터 기존 보드를 유지하고 카드를 교체할 수 있다.
- 최고 라운드가 계정별로 저장된다.
- 랭킹에서 사용자별 최고 기록이 정상적으로 정렬된다.

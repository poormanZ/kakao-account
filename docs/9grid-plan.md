# 9Grid 개발 기획

## 1. 게임 개요

**게임 제목:** 9Grid
**서브타이틀(가칭):** 9 Grid Survival

3×3 카드 보드와 속성/직업 시너지를 이용해 몬스터를 처치하고, 최대 몇 라운드까지 생존할 수 있는지를 경쟁하는 턴 기반 생존 전략 미니게임이다.

핵심 재미는 매 턴 제공되는 3장의 카드 중 원하는 카드만 리롤하고, 1장을 선택해 보드에 배치/교체하면서 현재 보드의 시너지를 최적화하는 것이다.

---

## 2. 핵심 게임 루프

```text
ROUND 시작
  ↓
최대 9 TURN
  ↓
[카드 리롤]
  ↓
[카드 1장 선택]
  ↓
[3×3 배치 또는 기존 카드 교체]
  ↓
[속성/직업 시너지 계산]
  ↓
[몬스터 전투]
  ↓
몬스터 처치?
  ├─ YES → ROUND CLEAR → 다음 ROUND
  └─ NO  → 플레이어 생존 여부 확인 → 다음 TURN
                    ↓
              9 TURN 종료
                    ↓
              몬스터 생존
                    ↓
                 GAME OVER
```

### 라운드 규칙

- 각 라운드는 최대 9턴으로 진행한다.
- 9턴 안에 몬스터를 처치하면 즉시 다음 라운드로 진행한다.
- 9턴이 끝났는데 몬스터가 살아 있으면 게임 오버다.
- 플레이어 HP가 0이 되면 즉시 게임 오버다.
- 최종 랭킹의 핵심 기준은 최대 클리어 라운드다.

---

## 3. 턴 진행

매 턴은 다음 순서로 고정한다.

```text
1. 카드 리롤
2. 카드 선택
3. 카드 배치/교체
4. 시너지 계산
5. 전투
6. 다음 턴 또는 다음 라운드
```

### 3-1. 카드 리롤

매 턴 3장의 후보 카드가 제공된다.

플레이어는 카드별로 `KEEP` 또는 `REROLL`을 선택할 수 있다.

리롤하지 않은 카드는 유지하고, 선택한 카드만 새 카드로 교체한다.

MVP 기본값은 턴당 1회 부분 리롤로 시작한다.

### 3-2. 카드 선택

최종적으로 보이는 3장의 카드 중 정확히 1장을 선택한다.

### 3-3. 배치/교체

- 보드에 빈칸이 있으면 선택한 카드를 빈칸에 배치한다.
- 보드가 완성된 이후에는 기존 카드 1장을 선택해 새 카드로 교체한다.
- 카드 교체 시 기존 시너지와 교체 후 예상 시너지를 비교할 수 있도록 UI에서 미리보기한다.

---

## 4. 3×3 보드

게임의 핵심 전략 공간은 3×3 보드다.

```text
┌─────┬─────┬─────┐
│     │     │     │
├─────┼─────┼─────┤
│     │     │     │
├─────┼─────┼─────┤
│     │     │     │
└─────┴─────┴─────┘
```

### 보드 구축

첫 라운드에서는 9턴 동안 카드 1장씩 배치해 보드를 완성한다.

```text
TURN 1 → 1장
TURN 2 → 2장
...
TURN 9 → 9장 / 3×3 완성
```

라운드 클리어 후에는 완성된 보드를 유지한다.

Round 2부터는 빈칸에 새 카드를 추가하는 대신 기존 카드 교체를 통해 빌드를 개선한다.

---

## 5. 카드 구조

모든 카드는 속성과 직업을 각각 하나씩 가진다.

```text
속성 + 직업
```

MVP 기본 카드 조합은 `4속성 × 4직업 = 16종`이다.

### 속성 4종

| 속성 | 역할 방향 |
|---|---|
| 🔥 불 | 공격력, 치명타, 지속 피해 |
| 💧 물 | 회복, 피해 감소, 보호막 |
| 🌪 바람 | 속도, 연속 공격, 회피 |
| 🪨 땅 | 방어력, 최대 HP, 안정성 |

### 직업 4종

| 직업 | 역할 방향 |
|---|---|
| 🛡 탱커 | 방어, 피해 흡수, 보호 |
| ⚔ 전사 | 직접 공격, 물리 피해, 처치 보너스 |
| ❤️ 힐러 | 회복, 버프, 디버프 해제 |
| 🔮 법사 | 스킬 피해, 광역 공격, 특수 효과 |

---

## 6. 시너지 시스템

가로 또는 세로로 연속된 3장의 카드가 같은 속성 또는 같은 직업이면 시너지가 발동한다.

### 속성 시너지

```text
🔥 🔥 🔥
```

→ 불 시너지

### 직업 시너지

```text
⚔ ⚔ ⚔
```

→ 전사 시너지

### 이중 시너지

하나의 3장 라인이 속성과 직업을 동시에 만족하면 두 시너지가 모두 발동한다.

```text
🔥⚔  🔥⚔  🔥⚔
```

→ 불 시너지 + 전사 시너지

### 판정 범위

- 가로 3칸: 3개 라인
- 세로 3칸: 3개 라인
- 대각선은 MVP에서 판정하지 않는다.
- 완성된 보드는 최대 6개 라인을 독립적으로 판정한다.

---

## 7. 시너지 설계 방향

정확한 수치는 플레이 테스트를 통해 조정한다. MVP에서는 각 시너지가 명확하게 다른 전략을 만들도록 설계한다.

### 속성 시너지

**불**
- 공격력 증가
- 치명타 확률 증가
- 지속 피해 강화

**물**
- 매 턴 회복
- 받는 피해 감소
- 보호막 강화

**바람**
- 추가 공격 확률
- 회피 확률
- 공격 속도/행동 보너스

**땅**
- 최대 HP 증가
- 방어력 증가
- 피해 감소/보호막

### 직업 시너지

**탱커**
- 피해 감소
- 보호막
- 생존 보너스

**전사**
- 공격력 증가
- 치명타/처치 보너스

**힐러**
- 회복량 증가
- 지속 회복
- 버프 강화

**법사**
- 스킬 피해 증가
- 광역 피해
- 특수 효과 강화

---

## 8. 전투 시스템

시너지 계산 후 현재 보드의 전투 능력치를 적용해 몬스터와 전투한다.

```text
현재 보드
  ↓
시너지 활성화
  ↓
플레이어 전투 능력 계산
  ↓
몬스터에게 피해
  ↓
몬스터 반격
  ↓
플레이어 HP 확인
```

전투는 매 턴 종료 시 1회 진행한다.

### 설계 원칙

- 초반에는 보드가 약하므로 몬스터를 빠르게 죽이기 어렵다.
- 턴이 지날수록 시너지가 늘어나며 플레이어가 강해진다.
- 몬스터도 라운드가 올라갈수록 강해진다.
- 공격에 집중하면 9턴 제한에 유리하지만 생존이 위험해진다.
- 방어에 집중하면 오래 버틸 수 있지만 9턴 안에 몬스터를 죽이지 못할 수 있다.

매 턴 플레이어는 공격력, 생존력, 시너지 구조를 동시에 판단한다.

---

## 9. 몬스터 시스템

매 라운드마다 하나의 몬스터가 등장한다.

기본적으로 라운드가 올라갈수록 HP와 공격력이 증가한다.

향후 특수 패턴을 추가한다.

- 방어형: 방어력이 높음
- 회복형: 일정 턴마다 HP 회복
- 광역형: 플레이어에게 큰 피해
- 암살형: 특정 턴에 강한 공격
- 속성 저항형: 특정 속성 피해 감소

### 보스

특정 라운드에는 보스를 배치한다.

```text
5R  MINI BOSS
10R BOSS
20R ELITE BOSS
30R BOSS
...
```

보스는 일반 몬스터와 다른 특수 규칙을 가져 현재 빌드의 조정을 유도한다.

---

## 10. 라운드 구조

### Round 1

튜토리얼 성격의 첫 라운드다.

- 빈 3×3 보드
- 9턴 동안 카드 배치
- 기본 속성/직업 시너지 학습
- 몬스터 처치

### Round 2+

완성된 보드를 유지한 상태로 시작한다.

- 매 턴 3장 후보
- 부분 리롤
- 1장 선택
- 기존 카드 1장 교체
- 시너지 재계산
- 전투

게임은 다음 두 단계의 재미를 갖는다.

```text
Round 1
보드 구축

Round 2+
보드 최적화 + 생존
```

---

## 11. 게임 오버

다음 조건 중 하나를 만족하면 즉시 게임 종료한다.

1. 플레이어 HP가 0이 됨
2. 해당 라운드의 9턴이 종료되었는데 몬스터가 생존함

게임 오버 결과 화면에는 최대 라운드, 최고 기록, 랭킹을 표시한다.

---

## 12. 랭킹

핵심 랭킹 지표는 최대 클리어 라운드다.

권장 타이브레이커:

1. 최대 클리어 라운드
2. 해당 라운드의 몬스터 처치 턴
3. 남은 HP
4. 기록 생성 시각

포털에서 노출하는 대표 기록은 최대 라운드 하나로 단순하게 유지한다.

### 계정 연동

게임 서비스는 계정 플랫폼의 내부 `users.id`를 `account_user_id`로 사용한다.

Kakao 사용자 ID나 Access Token을 게임 데이터의 식별자로 사용하지 않는다.

---

## 13. 점수/기록 저장

MVP에서는 게임별 별도 점수 테이블을 사용한다.

권장 테이블: `9grid_scores`

```text
id
account_user_id
max_round
last_round_clear_turn
remaining_hp
created_at
```

향후 검증/리플레이가 필요하면 다음 데이터를 추가한다.

```text
run_id
build_snapshot_json
round_stats_json
synergy_stats_json
```

클라이언트가 제출한 `max_round`를 그대로 신뢰하지 않는다. 장기적으로는 서버가 게임 진행 상태 또는 run session을 검증한 뒤 기록을 저장한다.

---

## 14. API 방향

게임 기록 API는 기존 인증/세션 시스템과 연동한다.

```text
GET  /api/games/9grid/ranking
GET  /api/games/9grid/my-rank
GET  /api/games/9grid/best
POST /api/games/9grid/scores
```

인증된 사용자의 내부 계정 ID를 기준으로 개인 기록을 조회한다.

## 16. MVP 범위

### 포함

- 3×3 보드
- 16종 기본 카드
- 4속성
- 4직업
- 부분 리롤
- 카드 1장 선택
- Round 1 보드 구축
- Round 2+ 카드 교체
- 가로/세로 시너지
- 기본 몬스터 전투
- 9턴 제한
- 게임 오버
- 최고 라운드 저장
- 기본 랭킹

### 제외

- 카드 수집/희귀도
- 장비
- 스킬 트리
- 복잡한 상태 이상
- PvP 실시간 대전
- 대각선 시너지
- 과도한 메타 성장 시스템

MVP의 목적은 카드 선택 → 보드 최적화 → 전투 → 생존이라는 핵심 루프가 재미있는지 검증하는 것이다.

## 17. 향후 확장

- Daily Seed: 모든 플레이어에게 동일한 카드 시퀀스를 제공해 순수 전략 경쟁
- 카드 희귀도 및 특수 카드
- 보드 효과
- 특수 몬스터 및 보스 패턴
- 리롤 횟수 증가 요소
- 시즌 랭킹
- 리플레이/런 기록
- 일일/주간 도전

1. 게임 상태 모델
2. 카드/보드 모델

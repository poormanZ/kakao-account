# 대장간 강화 미니게임 기획

## 1. 게임 개요

### 가칭
**대장간: 오늘도 강화**

플레이어가 대장장이가 되어 무기를 사고, 강화하고, 판매하면서 골드를 불리는 초간단 강화 미니게임이다.

핵심 재미는 다음 세 가지다.

- 낮은 가치의 무기를 반복해서 강화해 고가 무기로 만든다.
- 강화 성공 확률과 비용 사이에서 위험을 감수한다.
- 번 돈으로 강화 관련 스킬을 구매해 더 높은 강화에 도전한다.

게임은 짧은 세션으로 구성하며 복잡한 전투 없이 **구매 → 강화 → 판매 → 스킬 구매 → 재투자**의 반복만으로 플레이할 수 있도록 한다.

---

## 2. 핵심 게임 루프

```text
골드 획득
  ↓
0강 무기 구매
  ↓
강화 시도
  ↓
성공 → 강화 단계/데미지 상승
  │
  └ 실패 → 현재 무기 소실 또는 실패 페널티
  ↓
현재 무기 판매
  ↓
골드 증가
  ↓
스킬 구매
  ↓
강화 확률/보상 개선
  ↓
더 높은 강화 도전
```

MVP에서는 화면 이동을 최소화하고 한 화면에서 모든 행동이 가능하도록 한다.

---

## 3. 초기 플레이어 상태

게임 최초 시작 시 다음을 지급한다.

| 항목 | 초기값 |
|---|---:|
| 골드 | 10 |
| 무기 | 일반검 |
| 강화 단계 | +0 |
| 데미지 | 1 |

초기 무기는 판매할 수 있으며 판매 시 기본 데미지와 동일한 1골드를 받는다.

---

## 4. 무기 시스템

### 4-1. 무기 구조

MVP 무기는 다음 정보를 가진다.

```text
weapon_id
name
base_damage
enhancement_level
rarity
```

무기 이름/외형은 향후 확장한다. MVP에서는 여러 종류의 0강 무기를 랜덤으로 제공하되, 경제 밸런스는 `base_damage`를 기준으로 통일한다.

### 4-2. 데미지

강화 단계가 1 증가할 때마다 데미지는 2배가 된다.

```text
현재 데미지 = 기본 데미지 × 2^강화 단계
```

기본 데미지가 1인 일반검 예시:

| 강화 | 데미지 |
|---:|---:|
| +0 | 1 |
| +1 | 2 |
| +2 | 4 |
| +3 | 8 |
| +4 | 16 |
| +5 | 32 |
| +6 | 64 |
| +7 | 128 |
| +8 | 256 |
| +9 | 512 |
| +10 | 1,024 |

기본 데미지가 3인 무기는 +0에서 3, +1에서 6, +2에서 12와 같이 증가한다.

## 5. 강화 시스템

### 5-1. 강화 비용

강화 비용은 현재 강화 단계 기준으로 한다.

```text
+0 → +1 : 0 골드
+1 → +2 : 1 골드
+2 → +3 : 2 골드
+3 → +4 : 3 골드
+N → +(N+1) : N 골드
```

따라서 비용 공식은 다음과 같다.

```text
강화 비용 = 현재 강화 단계
```

강화 시도 전에 비용을 차감한다.

### 5-2. 기본 강화 확률

강화 단계가 높아질수록 성공 확률이 10%p씩 감소하는 구조를 기본값으로 한다.

```text
+0 → +1 : 90%
+1 → +2 : 80%
+2 → +3 : 70%
+3 → +4 : 60%
+4 → +5 : 50%
+5 → +6 : 40%
+6 → +7 : 30%
+7 → +8 : 20%
+8 → +9 : 10%
+9 → +10 : 5%
```

+9 이후는 기본 감소 규칙을 그대로 적용하면 0% 이하가 되므로 MVP에서는 최소 성공 확률을 5%로 둔다.

향후 최고 강화 단계가 올라가면 별도 확률 테이블을 정의한다.

### 5-3. 강화 성공

성공하면:

- 강화 단계 +1
- 데미지 2배
- 무기 가치 증가
- 성공 연출 표시

### 5-4. 강화 실패

MVP 기본 규칙은 **실패 시 무기 파괴**로 한다.

```text
강화 비용 지불
↓
확률 판정
↓
성공 → 강화 단계 +1
실패 → 현재 무기 파괴
```

실패 후 플레이어는 무기를 잃지만 골드는 유지한다. 따라서 높은 강화에 도전할수록 큰 판매 가치를 잃을 위험이 생긴다.

향후 스킬/등급 시스템으로 파괴 방지, 실패 시 단계 유지 등의 기능을 추가할 수 있다.

## 6. 무기 구매

상단 상점 영역에는 항상 구매 가능한 0강 무기 후보를 표시한다.

### 구매 규칙

- 모든 판매 무기는 0강 상태로 구매한다.
- 구매 가격은 무기의 기본 데미지와 동일하다.
- 구매 즉시 현재 장착 무기와 교체한다.
- 구매 가격을 지불한다.

예:

```text
철검 / 기본 데미지 1 / 가격 1G
강철검 / 기본 데미지 3 / 가격 3G
대검 / 기본 데미지 5 / 가격 5G
```

### 랜덤 상점

상단에 0강 무기 3개를 랜덤으로 제공하는 방식을 MVP 기본안으로 한다.

```text
[ 철검 ] [ 강철검 ] [ 대검 ]
  1G        3G        5G
 BUY        BUY       BUY
```

구매한 무기는 즉시 현재 무기가 된다.

상점은 일정 행동 후 또는 `REFRESH` 버튼으로 새로고침할 수 있으며, 초기 MVP에서는 무료 새로고침 또는 매우 저렴한 비용으로 시작해 경제 흐름을 쉽게 검증한다.

---

## 7. 무기 판매

현재 들고 있는 무기는 언제든 판매할 수 있다.

### 기본 판매 가격

```text
판매 가격 = 현재 무기 데미지
```

예:

| 무기 | 강화 | 데미지 | 판매가 |
|---|---:|---:|---:|
| 일반검 | +0 | 1 | 1G |
| 일반검 | +3 | 8 | 8G |
| 일반검 | +5 | 32 | 32G |
| 일반검 | +10 | 1,024 | 1,024G |

판매 시 무기는 소멸하고 골드가 증가한다.

판매 후에는 상점에서 새로운 0강 무기를 구매해 다시 도전한다.

---

## 8. 경제 구조

게임의 경제는 다음 구조를 기본으로 한다.

```text
낮은 가격의 0강 무기
        ↓
    강화 비용 투자
        ↓
강화 성공 → 가치 2배
        ↓
     판매
        ↓
 골드 회수/증가
        ↓
더 좋은 무기 또는 스킬 구매
```

중요한 경제 설계 원칙은 **강화가 항상 이득이 되지 않도록 하는 것**이다.

높은 강화에서는 실패 확률과 누적 강화 비용 때문에 현재 무기를 판매하고 다시 시작할지, 계속 강화할지 판단하게 한다.

---

## 9. 스킬 시스템

스킬은 골드로 영구 구매하며 게임 진행 중 계속 효과를 제공한다.

### 9-1. 강화 확률 +1%

```text
스킬명: 숙련된 대장장이
효과: 모든 강화 성공 확률 +1%p
가격: 초기 25G
```

예:

```text
기본 +3 → +4 : 60%
스킬 1레벨    : 61%
스킬 5레벨    : 65%
```

강화 확률은 최대 100%를 넘지 않는다.

### 9-2. 대성공 확률

```text
스킬명: 대장장이의 감
효과: 강화 성공 시 일정 확률로 추가 +2 강화
```

예:

```text
+3 강화 성공
→ 일반 성공: +4
→ 대성공: +5
```

대성공은 기본적으로 낮은 확률로 시작하며 스킬 구매 횟수에 따라 상승한다.

권장 MVP 수치:

```text
기본 대성공 확률: 0%
스킬 1회당: +1%
최대: 20%
```

대성공으로 추가 강화된 단계는 강화 비용을 추가로 지불하지 않는다. 대신 해당 강화 시점의 일반 성공 판정이 성공해야 대성공 판정을 시도한다.

### 9-3. 판매 금액 +1%

```text
스킬명: 장사의 달인
효과: 무기 판매 금액 +1%
```

예:

```text
기본 판매가 100G
판매 보너스 +5%
→ 105G
```

MVP에서는 소수점 골드를 사용하지 않고 최종 판매 금액을 내림 처리한다.

### 9-4. 스킬 구매 비용

스킬은 구매할수록 비용이 증가한다.

권장 공식:

```text
다음 구매 비용 = 기본 비용 × 2^현재 레벨
```

예:

| 스킬 | Lv0 가격 | Lv1 | Lv2 | Lv3 |
|---|---:|---:|---:|---:|
| 강화 확률 +1% | 25G | 50G | 100G | 200G |
| 대성공 +1% | 50G | 100G | 200G | 400G |
| 판매가 +1% | 30G | 60G | 120G | 240G |

초기 밸런싱 결과에 따라 가격/최대 레벨을 조정한다.

## 10. 화면 구성

게임은 모바일/PC 모두 한 화면에서 플레이할 수 있도록 구성한다.

```text
┌──────────────────────────────────────────┐
│ 🔨 대장간: 오늘도 강화       💰 125 G    │
├──────────────────────────────────────────┤
│              오늘의 상점                  │
│ [철검]       [강철검]       [대검]       │
│  DMG 1        DMG 3          DMG 5        │
│  1G BUY       3G BUY         5G BUY       │
├──────────────────────────────────────────┤
│             현재 장착 무기                │
│                                           │
│              ⚔ 일반검                    │
│               +7강                       │
│              DMG 128                     │
│                                           │
│     강화 비용: 7G     성공률: 30%        │
│                                           │
│       [ 🔨 강화하기 ]  [ 💰 판매 ]       │
├──────────────────────────────────────────┤
│                  스킬                      │
│ [숙련] +1%     [감] 대성공     [장사] +1% │
│    200G          400G          240G       │
├──────────────────────────────────────────┤
│ 강화 로그                                  │
│ +6 → +7 성공! DMG 64 → 128               │
└──────────────────────────────────────────┘
```

### UX 원칙

- 현재 골드를 항상 상단에 표시한다.
- 현재 무기의 강화 단계와 데미지를 가장 크게 표시한다.
- 강화 버튼에 **비용 / 성공 확률**을 함께 표시한다.
- 강화 실패 시 무기 파괴 여부를 명확하게 보여준다.
- 판매 예상 금액을 판매 버튼에 표시한다.
- 스킬은 현재 레벨 / 다음 효과 / 구매 비용을 한 번에 표시한다.
- 모바일에서는 상점 → 현재 무기 → 스킬 순서의 세로 레이아웃으로 전환한다.

## 11. 강화 연출

MVP에서도 강화 성공/실패의 손맛을 제공한다.

### 성공

```text
망치 타격
↓
불꽃/진동
↓
+N → +(N+1)
↓
DMG 2배 강조
```

### 대성공

```text
강한 불꽃
↓
CRITICAL!
↓
+N → +(N+2)
```

### 실패

```text
망치 타격
↓
금속 파손
↓
FAIL
↓
무기 파괴
```

애니메이션은 짧게 유지해 반복 플레이 속도를 방해하지 않는다.

## 12. 게임 상태 모델

MVP에서는 다음 상태를 관리한다.

```text
ForgeGameState
- gold
- current_weapon
- shop_weapons[]
- skills
- stats
- last_action
```

무기:

```text
Weapon
- id
- name
- base_damage
- enhancement_level
- rarity
```

스킬:

```text
ForgeSkills
- enhancement_bonus_level
- great_success_level
- sell_bonus_level
```

파생값:

```text
current_damage
upgrade_cost
upgrade_success_rate
sell_price
skill_costs
```

파생값은 서버와 클라이언트에서 동일한 규칙으로 계산할 수 있도록 순수 함수로 분리한다.

## 13. 서버 권한 및 보안

강화 게임도 골드 경제가 존재하므로 클라이언트가 최종 상태를 결정하지 않는다.

```text
Browser
  ↓ action
Game Server
  ↓ validate
Game State
  ↓ calculate RNG/result
Persisted State
  ↓
Browser
```

### 서버 권한

서버만 다음을 결정한다.

- 현재 골드
- 현재 무기
- 강화 비용
- 강화 성공 여부
- 대성공 여부
- 판매 금액
- 스킬 구매 가능 여부
- 스킬 레벨
- 상점 무기 목록

클라이언트가 다음과 같은 값을 직접 보내도 신뢰하지 않는다.

```text
success: true
new_level: 20
gold: 999999999
sell_price: 999999999
```

클라이언트는 다음과 같은 **행동 요청**만 전송한다.

```text
BUY_WEAPON
UPGRADE
SELL_WEAPON
REFRESH_SHOP
BUY_SKILL
```

서버가 현재 상태를 기준으로 결과를 계산한다.

### RNG

강화 확률 판정은 서버에서 수행한다.

```text
random < effective_success_rate
```

대성공도 서버에서 별도로 판정한다.

### 동시 요청 방지

동일한 사용자의 강화/판매/구매 요청이 동시에 처리되지 않도록 게임 상태 업데이트는 원자적으로 처리한다.

예:

```text
gold 10
upgrade cost 1

요청 A → 차감
요청 B → 이전 상태를 다시 사용하지 못하도록 거부/재검증
```

이를 통해 더블 클릭이나 병렬 요청으로 골드를 복제하는 문제를 방지한다.

## 14. 데이터 저장

게임 데이터는 기존 계정 데이터와 분리된 Game DB를 사용한다.

권장 테이블:

### forge_game_states

```text
id
account_user_id
gold
current_weapon_json
shop_weapons_json
skills_json
version
created_at
updated_at
```

`version`은 낙관적 동시성 제어에 사용할 수 있다.

### forge_action_logs

```text
id
account_user_id
action
result_json
created_at
```

MVP에서는 운영/디버깅에 필요한 최소 로그만 저장하며 민감한 인증정보는 저장하지 않는다.

향후 랭킹을 추가한다면 별도 `forge_scores` 또는 시즌 기록 테이블을 사용한다.

---

## 15. 저장/로그인 정책

- 비로그인 사용자는 체험 플레이를 허용할 수 있다.
- 게임 진행을 영구 저장하려면 로그인한다.
- 저장 식별자는 `kakao-account users.id`를 사용한다.
- Kakao Access Token은 게임 DB에 저장하지 않는다.
- 게임 DB에는 Kakao 고유 사용자 ID를 저장하지 않는다.

기존 미니게임 포털의 계정/게임 데이터 분리 원칙을 그대로 따른다.

## 16. MVP 범위

### 포함

- 대장간 테마
- 10G +0 일반검으로 시작
- 0강 무기 랜덤 상점
- 무기 구매
- 무기 강화
- 강화 확률 감소
- 데미지 2배 증가
- 강화 실패 시 무기 파괴
- 무기 판매
- 골드 표시
- 강화 확률 +1% 스킬
- 대성공 +1% 스킬
- 판매가 +1% 스킬
- 서버 권한 강화 판정
- 사용자별 게임 상태 저장

### 제외

- 무기 장비 슬롯 다수
- 방어구
- 몬스터 전투
- 재료/스크롤 시스템
- 무기 합성
- 길드
- PvP
- 복잡한 인벤토리
- 유료 결제
- 시즌 랭킹

MVP는 **강화와 골드 순환의 재미 검증**에 집중한다.

## 17. 향후 확장 후보

### 무기 등급

```text
일반 → 고급 → 희귀 → 영웅 → 전설
```

등급별 기본 데미지와 외형을 차별화한다.

### 강화 보호

- 파괴 방지권
- 실패 단계 유지
- 다음 강화 확률 보장

### 추가 스킬

- 강화 비용 감소
- 실패 시 골드 일부 환급
- 상점 슬롯 +1
- 무료 상점 새로고침
- 대성공 시 +3 강화 확률
- 판매 시 추가 고정 골드

### 장기 목표

최고 강화 기록 또는 시즌 최고 판매가를 경쟁 요소로 활용할 수 있다.

## 18. 밸런싱 기준

초기에는 수치 자체보다 **골드가 순환하면서 계속 강화하고 싶은지**를 검증한다.

특히 다음 구간을 집중적으로 확인한다.

```text
0~3강 : 초반 성장 체감
4~6강 : 리스크 발생 구간
7~9강 : 고위험 고수익 구간
10강+ : 엔드게임/기록 경쟁 구간
```

확인할 지표:

- 첫 무기 판매까지 걸리는 행동 수
- 평균 골드 보유량
- 강화 성공률 실제 체감
- 강화 실패로 인한 재시작 빈도
- 스킬 첫 구매 시점
- 최고 도달 강화 단계
- 세션 평균 플레이 시간
- 무기 판매 횟수
- 강화 실패 비율

## 21. 설계 결정 사항

1. 강화 확률은 클라이언트가 아닌 서버가 최종 판정한다.
2. 강화 성공 시 데미지는 강화 단계에 따라 2배가 된다.
3. 강화 비용은 현재 강화 단계와 동일하다.
4. 무기 구매 가격은 기본 데미지와 동일하다.
5. 무기 판매 가격은 현재 데미지를 기준으로 한다.
6. 강화 실패 시 MVP에서는 무기가 파괴된다.
7. 스킬은 영구 누적형이며 골드로 구매한다.
8. 강화 확률 보너스는 퍼센트포인트(`%p`)로 취급한다.
9. 게임 상태는 사용자별로 Game DB에 저장한다.
10. 게임 상태 변경은 서버에서 원자적으로 처리하여 골드/아이템 복제를 방지한다.
11. 게임의 첫 목표는 복잡한 콘텐츠가 아니라 **"한 번 더 강화해 볼까?"라는 반복 동기**를 만드는 것이다.

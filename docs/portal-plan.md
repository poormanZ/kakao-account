# 미니게임 포털 기획

## 1. 목적

`kakao-account`를 공통 계정 플랫폼으로 사용하여 여러 미니게임을 한 곳에서 탐색하고 실행하며, 게임별 랭킹을 확인하는 미니게임 포털을 구축한다.

핵심 책임은 다음처럼 분리한다.

- Account: 카카오 로그인, 세션, 공통 프로필, 사용자 식별
- Portal: 홈, 사용자 상태, 게임 목록, 게임/랭킹 진입
- Game: 게임 규칙, 점수 계산, 플레이 기록, 랭킹 데이터

## 2. 첫 화면

```text
┌──────────────────────────────────────────────────────────────┐
│ LOGO / HOME                         닉네임  [내 정보] [로그아웃] │
├──────────────────────────────────────────────────────────────┤
│                    MINI GAME PORTAL                          │
│                                                              │
│  ┌────────────────┐  ┌────────────────┐  ┌────────────────┐ │
│  │ GAME 01        │  │ GAME 02        │  │ GAME 03        │ │
│  │ 설명 / 아이콘   │  │ 설명 / 아이콘   │  │ 설명 / 아이콘   │ │
│  │ 최고 점수       │  │ 최고 점수       │  │ 최고 점수       │ │
│  │ [PLAY] [RANK]  │  │ [PLAY] [RANK]  │  │ [PLAY] [RANK]  │ │
│  └────────────────┘  └────────────────┘  └────────────────┘ │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 상단바

비로그인:
- 서비스 로고/홈
- `카카오로 로그인`

로그인:
- 닉네임
- 선택적으로 프로필 이미지
- `내 정보`
- `로그아웃`

상단바는 게임 화면과 랭킹 화면에서도 공통으로 유지한다.

### 게임 카드

필수 정보:
- 게임명
- 짧은 설명
- 아이콘/썸네일
- 로그인 사용자의 최고 점수
- `PLAY`
- `RANKING`

게임 카드에는 게임 내부 로직을 노출하지 않는다.

## 3. 사용자 정책

비로그인 사용자도 게임 목록과 전체 랭킹 조회는 가능하게 한다.

로그인이 필요한 기능:
- 점수 제출
- 개인 최고 기록 저장
- 내 랭킹 확인
- 계정 기반 게임 진행 저장

게임 특성상 가능하면 게스트 플레이 후 로그인하여 결과를 제출할 수 있도록 한다.

사용자 식별자는 항상 `kakao-account users.id`를 사용한다.

```text
account_user_id = kakao-account users.id
```

Kakao Access Token과 `kakao_user_id`는 게임 서비스에 전달하거나 식별자로 사용하지 않는다.

## 4. URL 구조

게임:

```text
/games/{game-slug}
```

랭킹:

```text
/games/{game-slug}/ranking
```

예:

```text
/games/reaction
/games/reaction/ranking
```

## 5. 게임 화면

공통 상단바 아래에 게임별 콘텐츠를 배치한다.

```text
GAME TITLE
게임 설명 / 규칙

┌────────────────────┐
│                    │
│     GAME AREA      │
│                    │
└────────────────────┘

SCORE: 1234   BEST: 1500

[RESTART] [RANKING]
```

포털 공통 UI와 게임 UI를 분리하여 새 게임 추가 시 기존 계정/포털 코드를 최소한으로 수정한다.

## 6. 랭킹 화면

게임별 독립 랭킹을 제공한다.

```text
GAME TITLE RANKING

순위 | 닉네임 | 점수
1    | Player A | 12000
2    | Player B | 11500
3    | Player C | 10900
...

내 기록: 37위 / 7,200점

[게임으로 돌아가기] [홈으로]
```

MVP에서는 게임별 최고 점수 1개를 대표 기록으로 사용한다.

확장:
- 일간/주간/월간
- 시즌
- 최근 기록
- 평균 점수

동점 규칙은 게임별로 명시하며, 기본값은 먼저 기록한 사용자를 우선한다.

## 7. 점수 보안

클라이언트가 제출한 점수를 그대로 신뢰하지 않는다.

```text
Browser → Game Server → 점수 검증 → Game DB → Ranking
```

MVP에서는 게임 위험도에 맞춰 검증 수준을 정하고, 경쟁성이 높은 게임부터 서버 검증을 강화한다.

## 8. 데이터 소유권

미니게임 전용 테이블은 `kakao-account`에 추가하지 않는다.

Account DB:
- users
- sessions
- user_settings

Game DB:
- 플레이 기록
- 최고 점수
- 랭킹
- 게임별 진행 데이터

게임 DB는 `account_user_id`를 계정 플랫폼의 `users.id`와 연결한다.

## 9. 게임 카탈로그

초기에는 정적 TypeScript 데이터로 관리한다.

최소 필드:

```text
slug
name
description
icon/thumbnail
status
sort_order
ranking_enabled
```

상태:
- `active`
- `maintenance`
- `coming_soon`

게임 수가 증가하면 별도 카탈로그 데이터로 이전한다.

## 10. UI/UX

데스크톱:
- 3~4열 게임 카드
- 충분한 카드 간격
- PLAY/RANKING 역할을 명확히 구분

모바일:
- 1~2열 카드
- 사용자 영역 축약
- 게임 영역 세로 화면 우선
- 랭킹 표는 핵심 컬럼 중심으로 축약

게임 상태는 `플레이 가능 / 점검 중 / 준비 중 / 로그인 필요`를 명확하게 표시한다.

## 12. 최종 기획 원칙

전체 구조를 다음 세 영역으로 고정한다.

1. **Account** — 누가 플레이하는가?
2. **Portal** — 어떤 게임을 선택하는가?
3. **Game** — 어떻게 플레이하고 어떤 점수를 얻는가?

이렇게 분리하면 게임 수가 늘어나도 계정 시스템을 다시 만들 필요가 없고, 각 게임의 랭킹/데이터 정책도 독립적으로 운영할 수 있다.

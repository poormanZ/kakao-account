# Escape Room 미니게임 제작 기획서

## 1. 게임 개요

### 1.1 제목
**ESCAPE ROOM : PRIME WORLD**

### 1.2 장르
- 웹 기반 방탈출 / 추리 / 퍼즐
- 4인 협동 플레이를 고려한 병렬 퍼즐 구조
- 스토리 중심의 단계형 퍼즐

### 1.3 핵심 콘셉트
플레이어는 갑작스럽게 정체불명의 이세계에 도착한다. 겉보기에는 평범하지만 곳곳의 숫자가 이상하다. 플레이어가 직접 숫자의 규칙을 발견하면서 이 세계가 **소수(PRIME NUMBER)를 기준으로 유지되는 세계**임을 알아낸다.

그러나 탈출을 위해서는 그 규칙을 따르는 것이 아니라, 오히려 규칙에서 벗어난 대상을 찾아야 한다.

> **이 세계의 규칙을 따르지 않는 존재만이 이 세계를 벗어날 수 있다.**

## 3. PHASE 0 — 이세계 도착

플레이어는 자신이 어떻게 이곳에 왔는지 기억하지 못한다. 익숙한 물건과 낯선 물건이 섞인 공간이며, 처음부터 PRIME이라는 단어를 설명하지 않는다.

숫자를 관찰하고 조합하는 과정에서 세계의 규칙을 스스로 발견하게 한다.

## 4. PHASE 1 — 문제 1: 노트북 로그인

문제 1은 **2개의 병렬 단서 카드**로 구성한다. 두 카드는 서로 다른 정보를 제공하지만 최종적으로 하나의 컴퓨터 로그인 정보를 완성한다.

### 4.1 카드 A — 색상 문장

카드에는 다음 문장이 적혀 있다.

> **Open our archive confirm performance.**

각 단어는 다음 색상으로 표시한다.

```text
Open       → 빨간색
our        → 파란색
archive    → 초록색
confirm    → 노란색
performance → 보라색
```

카드 하단에는 다음과 같은 5개의 색상 입력 슬롯이 있다.

```text
컴퓨터 아이디 :
[빨강] [파랑] [초록] [노랑] [보라]

컴퓨터 비밀번호 :
[빨강] [파랑] [초록] [노랑] [보라]
```

카드 A만으로는 숫자를 알 수 없으며, 카드 B의 Performance 그래프가 필요하다.

### 4.2 카드 B — Performance 그래프

두 번째 카드의 제목은 **Performance**이다.

그래프의 x축은 `1~12`이며, 소수 위치에서 성능이 크게 증가한다.

```text
x = 1  → 낮음
x = 2  → 높음 / 빨강
x = 3  → 높음 / 파랑
x = 4  → 낮음
x = 5  → 높음 / 초록
x = 6  → 낮음
x = 7  → 높음 / 노랑
x = 8  → 낮음
x = 9  → 낮음
x = 10 → 낮음
x = 11 → 높음 / 보라
x = 12 → 낮음
```

그래프의 색상 점은 `2, 3, 5, 7, 11`에만 표시한다. 그래프 아래에는 `2 / 3 / 5 / 7 / 11` 숫자 라벨을 별도로 표시하지 않는다. 플레이어가 **x축의 위치를 직접 읽어야** 한다.

특히 `x=3`의 점은 `x=2`보다 더 높은 값으로 표시하고, `x=12`는 다시 낮은 값으로 내려가도록 구성한다.

### 4.3 아이디 풀이

카드 A의 색 순서:

```text
빨강 → 파랑 → 초록 → 노랑 → 보라
```

카드 B에서 해당 색의 x값을 읽는다.

```text
빨강 → 2
파랑 → 3
초록 → 5
노랑 → 7
보라 → 11
```

아이디는 색상별로 대응하는 **소수의 이름을 사용**한다.

```text
PRIME
```

따라서:

```text
컴퓨터 아이디 = PRIME
```

### 4.4 비밀번호 풀이

같은 색 순서의 숫자를 그대로 이어 붙인다.

```text
빨강 → 2
파랑 → 3
초록 → 5
노랑 → 7
보라 → 11
```

따라서:

```text
2 + 3 + 5 + 7 + 11
= 235711
```

최종 로그인 정보:

```text
ID       : PRIME
PASSWORD : 235711
```

### 4.5 문제 1의 의도

문제 1에서는 게임이 시작하자마자 '소수'라고 알려주지 않는다.

플레이어가 다음 순서로 발견하도록 한다.

```text
색상이 있는 문장
      ↓
Performance 그래프 조사
      ↓
높은 점의 위치 확인
      ↓
2, 3, 5, 7, 11 발견
      ↓
소수라는 규칙 발견
      ↓
색상 ↔ 소수 연결
      ↓
PRIME / 235711 완성
```

### 4.6 웹 UI 구현 기준

첫 화면은 참고 카드 이미지와 같은 **두 장의 종이 카드 레이아웃**으로 구성한다.

- 좌측: 색상 문장 + 아이디/비밀번호 색상 입력선
- 우측: Performance 그래프
- 크림색/종이 질감 배경
- 얇은 검정 테두리와 모서리 장식
- 카드 상단/하단에 불필요한 `ESCAPE ROOM`, `CARD 01`, `PRIME WORLD` 등의 문구를 넣지 않는다.
- 그래프 하단의 `2, 3, 5, 7, 11` 숫자 라벨을 넣지 않는다.
- 모바일에서는 두 카드가 세로로 배치된다.

### 4.7 서버 검증

브라우저는 아이디와 비밀번호를 서버로 전달하고, 정답 판정은 Cloudflare Worker에서 수행한다.

```text
Browser
   │
   │ { id, password }
   ▼
Cloudflare Worker
   │
   │ server secret: ESCAPE_ROOM_KEY_1_1
   ▼
ACCESS GRANTED / ACCESS DENIED
```

서버 secret은 다음 형식으로 관리한다.

```text
ESCAPE_ROOM_KEY_1_1=PRIME|235711
```

클라이언트 JavaScript에는 최종 정답을 비교하는 로직을 넣지 않는다. 틀린 입력에 대해서도 예상 정답이나 부분 정답을 반환하지 않는다.

## 5. PHASE 2 — 생일 기록

노트북 로그인 성공 후 생일 기록으로 이동한다.

```text
10월 09일 — 1009
10월 11일 — 1011
10월 13일 — 1013
10월 19일 — 1019
10월 21일 — 1021
10월 31일 — 1031
```

소수 여부를 조사하면 1011만 비소수다.

```text

```

따라서 10월 11일의 **이민수(MINS)**가 외부인임을 추론한다.

## 6. PHASE 2.5 — 이민수의 다이어리

> 나는 이곳의 사람이 아니다.
>
> 처음에는 나도 이곳이 이상하다는 것을 몰랐다. 하지만 이곳의 사람들은 숫자를 너무 당연하게 받아들인다.
>
> 날짜도, 물건도, 길도 모두 같은 규칙을 따른다.
>
> 이곳에서는 **소수가 특별한 숫자가 아니다.** 오히려 소수가 아닌 것이 이상한 것이다.
>
> 그리고 이 세계에는 네 가지 색의 돌이 있다.
>
> 사람들은 그것을 **사색석(四色石)**이라고 부른다.
>
> 붉은 돌, 푸른 돌, 초록 돌, 노란 돌.
>
> 이곳에서는 사색석을 화폐처럼 사용한다.
>
> 네 돌의 가치는 서로 다르며, 그 값 역시 이 세계의 규칙을 따른다.
>
> **2, 3, 5, 7.**
>
> 하지만 어느 색이 어느 숫자를 의미하는지는 기록되어 있지 않다.
>
> **저울이 진실을 알려줄 것이다.**

## 7. PHASE 3 — 사색석 4인 병렬 퍼즐

4명의 플레이어가 동시에 서로 다른 장소의 단서를 조사하고 중앙에서 정보를 합친다.

```text
PLAYER A → 단서 A ┐
PLAYER B → 단서 B ├→ 중앙 저울 퍼즐
PLAYER C → 단서 C ┤
PLAYER D → 단서 D ┘
```

### 사색석

| 색상 | 이름 | 실제 가치 |
|---|---|---:|
| 🔴 붉은색 | 혈석 | 2 |
| 🔵 푸른색 | 청석 | 3 |
| 🟢 초록색 | 녹석 | 5 |
| 🟡 노란색 | 황석 | 7 |

토큰에는 숫자를 직접 표시하지 않는다.

### 단서 관계

```text
붉은 돌은 푸른 돌보다 가볍다.
초록 돌은 푸른 돌보다 무겁다.
노란 돌은 초록 돌보다 무겁다.
붉은 돌은 네 돌 중 가장 가볍다.
```

결과:

```text
붉은 < 푸른 < 초록 < 노란
```

후보 값이 `2, 3, 5, 7`이므로:

```text
붉은 = 2
푸른 = 3
초록 = 5
노란 = 7
```

실제 양팔저울과 숫자 추를 사용해 마지막으로 검증한다.


## 12. 퍼즐 설계 원칙

1. 답을 화면에 직접 노출하지 않는다.
2. 플레이어가 여러 단서를 연결해서 규칙을 발견하게 한다.
3. 문제 1은 2개의 카드로 분리하여 병렬 탐색을 유도한다.
4. 그래프는 소수 위치를 시각적으로 강조하지만 '소수'라는 단어를 먼저 알려주지 않는다.
5. 그래프 아래에 소수 숫자 라벨을 넣지 않아 x축 판독을 요구한다.
6. 카드 디자인은 실제 방탈출 인쇄물처럼 종이 질감과 색상 단서를 중심으로 한다.
7. 정답 검증은 서버에서 수행하고 클라이언트에는 정답 비교 로직을 두지 않는다.
8. 이후 단계에서도 PRIME/NON-PRIME의 발견이 스토리와 직접 연결되도록 한다.

## 15. 핵심 테마 연결

```text
1011 = 세계의 규칙을 따르지 않는 사람
8121 = 세계의 규칙을 따르지 않는 버스
```

처음에는 비소수가 '이상한 것'으로 등장하고, 마지막에는 그 비소수가 오히려 탈출구가 된다.

> **세계의 규칙에서 벗어난 존재가 곧 탈출구다.**
